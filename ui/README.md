# ui - PC configuration tool

## Start the UI
- Double-click the Desktop shortcut "PDM UI" (or `ui\Start PDM UI.cmd`): it builds the simulated boards if they are older than `main`, starts the simulator bridge (port 3333) and the app (port 5000) in minimised windows, and opens http://localhost:5000/pdm. Already running: it only opens the browser.
- Options (`ui\Start-PdmUi.ps1`): `-Stop` (stops only what the launcher started), `-NoSim` (app only), `-Rebuild` (build the sim again), `-InstallShortcut` (make the Desktop shortcut again), `-SelfTest`; `-Port` / `-BridgePort` / `-SoDir` for a second copy.
- The app connects to the simulated boards by itself (launch flags `--PdmAutoConnect:Adapter "SLCAN TCP" --PdmAutoConnect:Port localhost:3333 --PdmAutoConnect:BitRate 1000K`, passed by the launcher; with `-NoSim` it passes `--PdmAutoConnect:Last true` = the adapter of the last successful Connect; `-NoAutoConnect` = pick the adapter by hand: "SLCAN TCP", `localhost:3333`, 1000K). Then press "New PDM" or "Load the ST185 starter" on /pdm.
- Play with the simulated boards while the app is connected: write lines into `<so dir>/ctl<bridge port>` in WSL (default `/home/daniel/scratch/ui-play/so/ctl3333`), e.g. `wsl -e bash -c "printf 'IN B 0 12v\nLOAD B 2 40\n' > /home/daniel/scratch/ui-play/so/ctl3333"`: `IN <board> <i> <open|gnd|12v>`, `LINK <board> <on|off>`, `LOAD <board> <o> <amps>`, `TEMP <board> <C>`, `AN <board> <volts>`, `RESTART <board> ...` (power cycle, burned settings kept), `T <id hex> <data hex>` (one frame), `TXP <id hex> <data hex|off> [period ms]` (a repeating frame, e.g. the ECU's 0x3F4); inputs and outputs count from 0 (`ui/tests/sim_bridge.py` `play_ctl`).

`dingoConfig/` is upstream dingoConfig (MIT, licence in `dingoConfig/LICENSE`), copied in the same way dingoFW lives in `firmware/` (DECISIONS 2026-11-10 B2a, K1a route A). Nothing goes upstream.

- Upstream: https://github.com/corygrant/dingoConfig, branch `development`, commit `01134ad057dee5c69788ccfecf63420740e932bc` (2026-10-26, "bump version"). It matches our firmware's dingoFW `development` @ 14084e9.
- Import commit: unmodified copy (tree hash equal to upstream `e9202a9`). Our changes are separate commits on top, so `git diff <import commit> -- ui/dingoConfig` shows all of them.
- Build output (`bin/`, `obj/`) is git-ignored.

- Route B phase B4 (w1 recipe, DECISIONS 2026-11-16, proven in `firmware/sim` s1 S7): /pdm "Links" panel (`dingoConfig/web/Components/CustomPdm/PdmLinksPanel.razor`, logic `dingoConfig/domain/CustomPdm/PdmLinks.cs`): any of the 24 digital inputs as the trigger of any output; per output: source input, loss mode, condition. Same board: the output uses the input directly. Other board: nothing is set on the input board P; on the output board Q one stock CAN input L listens to one bit of P's msg 37 (base + 0x27, every 100 ms), Equal 1. Loss mode per output (u3c / w1, default off): off = L (time-out 1 s), hold = L without time-out (off at power-up), on = virtual input `LOST OR L`, condition = `(LOST AND C) OR L` (C = an input / condition of Q, picked in the panel). Shared per source board on Q while it has on / condition links: ALIVE (CAN input on P's msg 37, bit 0, `>= 0`, time-out on), SEEN (same, time-out off) and LOST = `SEEN AND NOT ALIVE`, made with the first such link and freed with the last; LOST always gets a lower virtual-input index than every link virtual input (else a 2 ms drop at the time-out). No critical start-up exception (DECISIONS 2026-11-16): every linked output stays off until boot is done and P's first frame has arrived; a board read back with the dropped critical recipe (`NOT ALIVE` in place of LOST) shows "old recipe" and Upgrade converts it (mode and condition kept). Cost on Q: per source board 2 CAN inputs + 1 virtual input; per link 1 CAN input (+ 1 virtual input for on / condition). Ownership: a CAN input / virtual input is ours only when every field matches one of these patterns (ID = another board's msg 37); old B4 "on" links (slot Equal 0 + `NOT slot OR false`, on at power-up until the first frame) are shown as "old recipe" and converted only by the Upgrade button (one confirm); anything else is the user's and never changed. Free = disabled with ID 0 (virtual input: disabled, no variables), never A2's fan CAN inputs 25-28, fan virtual inputs 12-14 or the load-shed ones 15-16; the lowest free one is used; a refused edit changes nothing. An output whose trigger is set by something else asks "already assigned. Overwrite?" (g1). Links live only in the boards' params, so Read All / an app restart shows them again; base-ID Move takes link and ALIVE / SEEN slots along. Refused: the fan output (A2 OUT2), a paired output. Measured on the sim through the /pdm Write All + Burn and a power cycle (`PdmW1LiveSimTests`, 0.5 ms steps): linked outputs 0 ms ON before P's first frame (P silent 1.5 s, key on with both boards, key on with P's input OFF), on 3 ms after it; at loss one clean change 1005 ms after the last frame, no blip on outputs whose mode keeps their state. Input -> output pin 47-125 ms across boards, 25 ms on the same board (B4). Sim bridge: `PIN <board> <o>` reads an output pin, `RESTART <board> ...` power-cycles boards (FRAM kept), `TRACE` records pin changes.
- Read on connect (p2a): when a board (type 14 / 15) connects, /pdm reads it by itself (a Read All of just the boards that connected, one after another, through `PdmOps`); while a Read All / Write All / Burn runs, it waits and goes after the run. If the PC holds unsaved edits for that board, /pdm asks instead: "Keep PC settings" (nothing read, Write All later) or "Take the board's" (Read All of that board). Nothing is written or burned by it. "Unsaved edits" = the board's PC param values differ from a snapshot of them taken on the stock "Read Successful" / "Write Successful" of that device in this session (from /pdm or the board's own page; the board card shows "PC changes not written"). No snapshot yet: a New PDM board counts as edited until written; a hand-added device does not (it cannot be written before a Read All anyway); a board loaded from a project file saved with a complete set does (uipolish, below). The config CRC check is not used for it: a mismatch cannot tell a PC edit from a board changed elsewhere. The check is made again every 100 ms, so a board that waits and gets edits is asked about, and an asked board whose edits are gone (written, or undone) is read. Connect = offline to connected as seen by the `PdmOpsService` timer (on from the first /pdm visit; the first look counts as a connect). Logic `dingoConfig/domain/CustomPdm/PdmAutoRead.cs`; switched on in `web/Program.cs`.

## Run on DansPC (PowerShell, repo root)
Build and start the app (then open the address it prints):

    dotnet build ui\dingoConfig\dingoConfig.sln
    dotnet run --project ui\dingoConfig\web\web.csproj

Build the firmware host sim once (WSL), from a committed branch:

    wsl -e bash -c 'S=~/scratch/ui-sim; rm -rf $S; mkdir -p $S/src $S/so; cd /mnt/c/projects/active/custom-pdm; git archive main firmware | tar -x -C $S/src; cd $S/src/firmware; for u in 1 2; do bash sim/build.sh custompdm_a $S/so $u; done; bash sim/build.sh custompdm_b $S/so 1'

Tests (without `CUSTOMPDM_SIM_SO` the live ones are reported as Skipped):

    dotnet test ui\tests\CustomPdm.Tests
    $env:CUSTOMPDM_SIM_SO='/home/daniel/scratch/ui-sim/so'; dotnet test ui\tests\CustomPdm.Tests

Use the app with the simulated boards (A1 0x500, A2 0x540, B 0x580, 1000K): start the bridge, then in dingoConfig pick adapter "SLCAN TCP", port `localhost:3333`, bit rate 1000K, add the three devices (types "custom-pdm A" / "custom-pdm B"), and open /pdm: it reads the connected boards by itself (read on connect, p2a) before any write (a hand-added device holds stock dingoPDM defaults, not our factory defaults). One Write All takes about 5.6 s per board through the bridge (measured 2026-11-21: A1 5.6 s, A2 5.6 s, B 5.8 s; 41 s per board before the pacer fix, uipolish above). The /pdm Write All has no fixed wait: per board, it restarts on every frame the PC sends to that board and every config reply from it, fails "no reply (no answer for 10 s while writing)" 10 s after the last one, and gives up at 5 min per board ("write not confirmed in 5 min"):

    wsl -e python3 /mnt/c/projects/active/custom-pdm/ui/tests/sim_bridge.py /home/daniel/scratch/ui-sim/so --slcan-tcp 3333
